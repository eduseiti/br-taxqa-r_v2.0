RAG pipeline

A plain dense pipeline, so that only the chunk unit varies

1 · Embed

jua-4B-mixed, a legal fine-tune of Qwen3-Embedding-4B; queries with a task instruction

2 · Retrieve

Dense top-1000 per strategy; no reranker, no hybrid

3 · Select

Rank order into a 4,000-token budget; drop or merge a chunk contained in a higher one

4 · Generate

Claims, each with a verbatim quote of ≤ 30 words; abstention allowed

5 · Score

LLM judge labels each gold nugget against the answer

Equal budget, not equal k

Strategies are compared at the same context size in tokens. Smaller chunks buy more distinct provisions, not more text.

A grounded prompt

Answer only from the numbered provisions; reference date tax year 2023; no value, law or year absent from them.

Pinned and logged

Model snapshots and providers pinned; tool use and web search refused; every call in a cost ledger.

We deliberately kept the pipeline simple: one dense retriever, no reranker, no query rewriting, so that differences come from the chunk unit. Context selection fills a token budget in rank order; if a chunk is contained in one already selected (an inciso inside its article), it is skipped or merged, so S2 does not waste budget on duplicates. Comparing at equal token budget rather than equal number of chunks is important: at equal k, S1 would simply get more text. The 4k budget is the middle of the retrieval range we measured (1k to 16k) and matches the oracle setting. The generator prompt asks for claims with verbatim quotes, which gives us grounding checks and citations to score. The embedding endpoint was checked against a local reference implementation before the corpus run.
